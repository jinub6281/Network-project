# 3일차 작업 계획서

- 날짜: 2026.11.07

## 1. 목표

- 각 부서 내부에서 네트워크 통신이 가능하도록 IP 할당 및 서브넷팅
- Vlan 을 활용한 망분리 및 보안 설정
- 용도별로 VLAN 망을 분리하는 작업

## 2. 작업 대상

| 대상 | 무엇을 |
|------|--------|
| HQ-SW2 (새로) | 2층 스위치. 기본 잠금, VLAN, 트렁크, 관리 주소          |
| HQ-SW3 (새로) | 3층 스위치. 기본 잠금, VLAN, 트렁크, 관리 주소          |
| HQ-SW1      | VLAN, 포트 배정, 쓰지 않는 포트 닫기, 트렁크 두 곳, 관리 주소 |
| HQ-R1       | Gi0/0의 주소를 서브인터페이스 다섯 개로 옮기기             |
| PC 5대       | 인사팀, 개발팀, 서버, 관리자, 2층 영업팀                |
|    | 설계표에 VLAN 칸, 구성도 첫 판                     |

## 3. 작업 내용

1. subnet ID 1 = 10, 2 = 20, 3 = 30, 4 = 40으로 vlan 생성
2. 인트라 관리를 위한 vlan 99, 999, 900을 추가 생성
3. 999(UNUSED) vlan을 활용해서 포트 보안을 설정
4. 99(NATIVE) vlan으로 각 부서별 스위치에 vlan 설정을 공유(trunk) 설정을 진행
5. SW1 > R1 인터페이스에 trunk 설정을 통해 vlan 설정을 적용, R1에 가상 인터페이스를 생성하여 10, 20, 30, 40 vlan이 서로 통신이 가능하도록 설정
6. VTP 설정으로 SW1 = server, SW2.3 = client 설정을 적용하여 vlan 태그 설정을 서로 공유하도록 만듬

## 4. 확인 방법

| 확인할 것 | 방법 | 기대하는 결과 |
|-----------|------|---------------|
| 포트가 VLAN에 들어갔다      | `show vlan brief`            | 부서별 포트 목록, 트렁크는 목록에 없음           |
| 트렁크가 섰다             | `show interfaces trunk`      | Gi0/1, Gi0/2 trunking, 허락한 VLAN만 |
| 같은 VLAN이 두 스위치를 건넌다 | Sales-PC1에서 Sales-PC3으로 ping | Reply                            |
| 다른 VLAN은 라우터를 지난다   | Sales-PC1에서 HR-PC1으로 tracert | 첫 줄이 192.168.10.1                |
| 주소를 바꿔도 못 넘어간다      | HR-PC1을 영업팀 대역 주소로 바꾸고 ping  | Request timed out                |
| 관리 접속               | Admin-PC에서 두 스위치로 telnet     | 비밀번호 창                           |
| VLAN이 설정 텍스트에 남는다   | `show running-config`        | `vlan 10` 줄                      |

## 5. 되돌리는 방법

-저장 전이면 `reload` 에서 저장하지 않음
-라우터가 꼬이면 `configs/HQ-R1.txt` 의 2일차 설정을 붙여 넣는다
-패킷트레이서 파일은 `git restore configs/network.pkt` 로 마지막 커밋의 판으로 돌아간다
